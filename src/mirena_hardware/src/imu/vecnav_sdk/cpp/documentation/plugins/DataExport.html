Data Export¶

The Data Export plugin allows the user to export data from a VectorNav unit into various file types, such as a CSV, TXT, RINEX, IMR, or BIN file. Data can be exported from previously recorded log files as well as directly from a VectorNav unit in real time. Additionally, this plugin supports exporting to multiple file formats at once, including exporting any skipped byte data to a separate BIN file.

Each of the following exporter types can be obtained from the Exporter class.

  • ExporterAscii - exports to a TXT file

  • ExporterCsv - exports to a CSV file

  • ExporterSkippedByte - exports to a BIN file

  • ExporterRinex - exports to a RINEX file

  • ExporterImr - exports to a IMR file

This Data Export plugin can be used in conjunction with the Logger plugin, which allows users to log all bytes received from the VectorNav unit to a binary file without the parsing of any packets. Any files logged from the Logger plugin can then be exported into the desired file formats using this Data Export plugin. Information on how to log data from a VectorNav unit into a binary file can be found on the Logger page.

Usage¶

There are two ways to use the Data Export plugin: exporting data from a previously logged file or connecting to a VectorNav unit and exporting the data in real time.

Exporting from a File¶

When exporting data from a previously recorded log file, a Sensor object must first be created to process the logged data. Because the Exporter class works with raw packets, it does not require the use of the CompositeData class for parsing. Therefore, the Sensor object should be configured with MeasQueueMode::Off.

Sensor::MeasQueueMode pushToCompositeData = Sensor::MeasQueueMode::Off;  // do not parse to CompositeData because that is not needed by exporters
std::array<uint8_t, 65536> byteBufferArray{};  // using statically allocated main byte buffer to be able to read more of the file at once (could
                                               // alternatively change 'mainBufferCapacity' in Config.hpp)
std::array<uint8_t, 2048> fbBufferArray{};

Sensor sensor(byteBufferArray, fbBufferArray, pushToCompositeData);

The desired Exporter object should then be created. The ExporterAscii class can only export logged ASCII output messages from the VectorNav unit, while the ExporterCsv class can export both ASCII and binary output messages. The ExporterSkippedByte class exports bytes that do not belong to any valid packet format, which is useful for debugging communication issues and data corruption. Once the Exporter object is created, the Sensor object must subscribe to the exporter’s message queue.

DataExport::ExporterAscii asciiExporter(outputDirectory, PacketQueueMode::Retry);
sensor.subscribeToMessage(asciiExporter.getQueuePtr(), "VN");

DataExport::ExporterCsv csvExporter(outputDirectory, PacketQueueMode::Retry);
sensor.subscribeToMessage(csvExporter.getQueuePtr(), "VN");
sensor.subscribeToMessage(csvExporter.getQueuePtr(), Sensor::SyncByte::FA);

DataExport::ExporterSkippedByte skippedByteExporter(outputDirectory, PacketQueueMode::Retry);
sensor.subscribeToMessage(skippedByteExporter.getQueuePtr(), Sensor::SyncByte::None);

Before connecting Sensor object to the file, the Exporter object must be started. This will kick off a separate thread for the Exporter object. .. tab:: ASCII

asciiExporter.start();

csvExporter.start();

skippedByteExporter.start();

Once the different Exporter has been started, the Sensor object should be used to connect to the log file, which will begin the exporting process.

sensor.connect(filePath);

Because the file is processsed in a background thread, the AsyncError queue should be monitored to detect when the end of the file is reached. A FileReadFailed error indicates that the end of the file has been reached and processing is complete. The Sensor object can then be disconnected from the log file.

sensor.disconnect();

After exporting the data, the exporter should be stopped to ensure all buffered data is written.

asciiExporter.stop();

csvExporter.stop();

skippedByteExporter.stop();

Exporting in Real Time¶

When using the Data Export plugin to export data in real time from a VectorNav unit, it is first necessary to create a Sensor object and connect to the VectorNav unit, such as by using the autoConnect() method.

Sensor sensor;
Error latestError = sensor.autoConnect(portName);

Once the VectorNav unit is connected, the Exporter object should be created.

DataExport::ExporterCsv csvExporter(outputDirectory);

In order for the Exporter object to export the desired messages from the sensor, the Sensor object must subscribe to the exporter’s message queue. In the example below, the ExporterCsv object is used to filter for binary packets with an “0xFA” sync byte.

latestError = sensor.subscribeToMessage(csvExporter.getQueuePtr(), Sensor::SyncByte::FA);

The ExporterCsv object can subscribe to multiple message types at once. For example, while subscribing to the binary packets with an “0xFA” sync byte, the ExporterCsv object can also subscribe to ASCII messages that begin with “VN”.

latestError = sensor.subscribeToMessage(csvExporter.getQueuePtr(), "VN", Sensor::AsciiSubscriberFilterType::StartsWith);

The Exporter object has now been set up, but has not yet begun exporting data. To begin exporting the subscribed messages, the Exporter object must be started. After all desired data has been exported from the VectorNav unit, the Exporter object must be stopped. This ensures all buffered data is exported to the output file.

Tip

Ensure the VectorNav unit is configured to output the desired data before starting the exporter.

csvExporter.start();
std::cout << "Logging to " << outputDirectory << std::endl;

std::this_thread::sleep_for(5s);
csvExporter.stop();
