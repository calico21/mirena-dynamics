Calibration¶

Note

Access to the Calibration Plugin requires a license agreement; it will not be provided until the agreement is signed—please email VectorNav Support at support@vectornav.com to initiate the licensing process.

The Calibration Plugin offers several different tools for the user to take advantage of.

  • Hard and Soft Iron (HSI) Calibration - Accounts for any time-invariant magnetic disturbances fixed with respect to the VectorNav unit

  • Bias Calibration - Estimates the accelerometer and gyroscope biases

  • Static IMU Calibration - Estimates the static accelerometer bias of the VectorNav unit and estimates the reference frame rotation between the VectorNav unit and a platform it is mounted to.

Hard and Soft Iron (HSI) Calibration¶

A magnetometer is used to measure the strength and direction of the local magnetic field surrounding a system. This magnetic field measurement can then be compared to models of Earth’s magnetic field to determine the heading of a system with respect to magnetic North. While seemingly straightforward, using a magnetometer to accurately estimate heading can prove to be quite challenging as Earth’s magnetic field is relatively weak and there often exist a number of different magnetic disturbances that can impact magnetometer measurements.

To account for any magnetic disturbances that are time-invariant and fixed with respect to the VectorNav unit, VectorNav has developed a Hard and Soft Iron Calibration tool. It is recommended to perform this calibration if the VectorNav unit requires an accurate heading solution, and either does not have access to GNSS, or will be operating in GNSS denied areas for extended periods of time. Additionally, it is typically recommended that an HSI calibration be performed on VectorNav’s single-antenna GNSS/INS products for robustness, particularly if the system will experience static and/or low-dynamic conditions. An HSI calibration is not usually required for VectorNav’s dual-antenna GNSS/INS products if the GNSS compass is active, but it should be performed for robustness if GNSS outages are expected. More information about the HSI calibration can be found in the Hard and Soft Iron technical note available on the VectorNav website.

Motion Requirements¶

The HSI calibration can be implemented using two different types of motion - a 2D calibration or a 3D calibration depending on the range of movement feasible during calibration. Typically, a 2D calibration is sufficient if the platform will stay between 5° to 10° of level in both pitch and roll. Outside of that range, a full 3D calibration is strongly recommended.

A 2D calibration requires that the VectorNav unit be rotated 360° about the axis parallel to gravity. The unit should be rotated on a flat surface with less than 10° of tilt. During a 2D calibration, the unit does not necessarily need to travel in a full circle — simply spinning the unit in place is sufficient.

When performing a full 3D calibration, the unit needs to be rotated about all axes to cover as much as possible a sphere of measurement. To achieve this, the following steps are recommended:

  1. Align the unit x-axis to the North-South vector and rotate a full 360°

  2. Repeat Step 1 for the y- and z-axes, aligning each to the North-South vector and rotating the unit a full 360°

  3. Align the unit x-axis to the East-West vector and rotate a full 360°

  4. Repeat Steps 1-3 for the y- and z-axes, aligning each to the East-West vector and rotating the unit a full 360°

If this type of motion is not feasible, contact VectorNav support for feedback on other viable motion profiles.

Usage¶

Note

When performing an HSI calibration, the latitude and longitude of the unit must be known.

The HSI calibration can be run either by from a previously logged data file or while connected to the VectorNav unit.

Performing an HSI Calibration from a Data File¶

When performing an HSI calibration using recorded data from a VectorNav unit, a HsiConfig object must first be created. This allows the user to define the parameters needed for calibration. The sensor’s latitude and longitude must be provided so the calibration algorithm can accurately reference the local magnetic field. The number of patches can also be configured, which defines how the measurement space is divided for data collection. This setting determines when measurements are retained, based on whether the magnetic field vector, or the vector perpendicular to it (east), passes through a given patch. For a 3D calibration, the number of data points can also be configured. This parameter controls how measurements are retained within each patch, either by limiting the total number of stored data points or by retaining measurements when the unit’s attitude changes by at least 360/numDataPointsPerPatch degrees, ensuring uniform orientation coverage within each patch.

If performing a 2D calibration motion profile, the Hsi2d object will be used.

Calibration::Hsi2dConfig hsiConfiguration;
hsiConfiguration.longitude = -96.7;
hsiConfiguration.latitude = 32.5;
hsiConfiguration.numPatches = 360;

Calibration::Hsi2d hsi(hsiConfiguration);

If performing a 3D calibration motion profile, the Hsi3d object will be used.

Calibration::Hsi3dConfig hsiConfiguration;
hsiConfiguration.longitude = 34.8;
hsiConfiguration.latitude = 31.9;
hsiConfiguration.numPatches = Calibration::NumPatches::Patches122;
hsiConfiguration.numDataPointsPerPatch = 10;

Calibration::Hsi3d hsi(hsiConfiguration);

When processing data from a previously recorded log file, a Sensor object must first be created and should be configured with MeasQueueMode::Retry.

Sensor::MeasQueueMode pushToCompositeData = Sensor::MeasQueueMode::Retry;  // do not allow overruns
Sensor sensor(pushToCompositeData);

Next, connect to the Sensor object using the inputted file path.

sensor.connect(filePath);

The data from the logged file is then loaded into the CalBase object for processing using the addMeasurement() method.

while (auto meas = sensor.getNextMeasurement())
{
    latestError = hsi.addMeasurement(*meas);
    if (latestError == Calibration::ErrorCal::None) { continue; }
    else if (latestError == Calibration::ErrorCal::IgnoredMeasurement) { ignoredCnt++; }
    else { std::cout << "Measurement " << ignoredCnt + hsi.getNumMeasAdded() << ": " << latestError << std::endl; }
}

To close the file, disconnect from the Sensor object.

sensor.disconnect();

Finally, solve and print out the HSI calibration results. This calibration solution should then be applied to the Magnetometer Calibration register (Register 23) on the VectorNav unit. A writeSettings() command should be issued to the sensor in order for the calibration values to persist through a reset or power cycle of the sensor.

latestError = hsi.solve();
if (latestError != Calibration::ErrorCal::None)
{
    std::cerr << latestError << " encountered during solve." << std::endl;
    return (int)latestError;
}
std::cout << hsi.solution;

Performing an HSI Calibration on a Connected VectorNav Unit¶

When performing an HSI calibration with a connected VectorNav unit, a Sensor object first needs to be created. This object should then be used to connect to the VectorNav unit, such as by using the autoConnect() method.

Sensor sensor;
Error latestError = sensor.autoConnect(portName);

Once the Sensor object has been created and connected to the VectorNav unit, a HsiConfig object must first be created to define the calibration parameters. Once the configuration is set, either a Hsi2d or Hsi3d object should be created which will be where the calibration measurements are added, and the calibration is solved. The sensor’s latitude and longitude must be provided so the calibration algorithm can accurately reference the local magnetic field. The number of patches can also be configured, which defines how the measurement space is divided for data collection. This setting determines when measurements are retained, based on whether the magnetic field vector, or the vector perpendicular to it (east), passes through a given patch.

If performing a 2D calibration motion profile, the Hsi2d object will be used.

    Calibration::Hsi2dConfig hsiConfiguration;
    hsiConfiguration.longitude = -96.7;
    hsiConfiguration.latitude = 32.5;
    hsiConfiguration.numPatches = 212;

    Calibration::Hsi2d hsi(hsiConfiguration);

If performing a 3D calibration motion profile, the Hsi3d object will be used. For a 3D calibration, the number of data points can also be configured. This parameter controls how measurements are retained within each patch, either by limiting the total number of stored data points or by retaining measurements when the unit’s attitude changes by at least 360/numDataPointsPerPatch degrees, ensuring uniform orientation coverage within each patch.

    Calibration::Hsi3dConfig hsiConfiguration;
    hsiConfiguration.longitude = 34.8;
    hsiConfiguration.latitude = 31.9;
    hsiConfiguration.numDataPointsPerPatch = 10;
    hsiConfiguration.numPatches = Calibration::NumPatches::Patches122;

    Calibration::Hsi3d hsi(hsiConfiguration);

Next, the VectorNav unit must be properly configured for the calibration data collection. This can be done by creating a CalSensorConfig object, and calling the prepareSensorForCalibration() method. This method will read and store the VectorNav unit’s initial configuration and then write the required register settings for the calibration data collection. It is recommended to perform a WriteSettings command and save the current VectorNav unit’s settings by performing a Register Scan before calibration.

Calibration::CalSensorConfig calSensConfig(&sensor, &hsi, Registers::System::AsyncOutputType::SerialPort::ActiveSerial, imuRate, gnssAided);
latestError = calSensConfig.prepareSensorForCalibration();
EXIT_IF_ERROR("Encountered when configuring Sensor for calibration.")

After the VectorNav unit has been properly configured, the KnownMagneticDisturbance command must be set to Present before collecting data for calibration.

latestError = sensor.knownMagneticDisturbance(KnownMagneticDisturbance::State::Present);
EXIT_IF_ERROR("Encountered when enabling KnownMagneticDisturbance")

To collect data when performing an HSI calibration on a connected VectorNav unit, a separate thread or loop needs to be created to get the sensor’s most recent measurement and add it to the HsiConfig object. In the HsiFromSensor example, this thread is started and stopped by the user pressing the Enter key. It is recommended that the user configure the thread or loop to their application as it is not required the that the measurements be added to the HsiConfig object using a key press.

Thread thread(&getStopChar, &stopFlag);
thread.detach();

void getStopChar(std::atomic_bool* flag);

#define EXIT_IF_ERROR(message)                                     \
    if (latestError != Error::None)                                \
    {                                                              \
        std::cerr << latestError << " : " << message << std::endl; \
        return static_cast<int>(latestError);                      \
    }

While the calibration thread or loop is running, the Sensor object is reading the measurements that were configured when setting the prepareSensorForCalibration() function. These measurements are added to the HSI calibration. It is during this time that the motion requirements for the HSI calibration are performed. Once all motion requirements have been fulfilled, the thread or loop should be stopped and no more measurements should be added to the HsiConfig object.

while (!stopFlag.load())
{
    auto meas = sensor.getMostRecentMeasurement();
    if (!meas) continue;

    calError = hsi.addMeasurement(*meas);

    if (calError == Calibration::ErrorCal::MaximumMeasurementsRecorded)
    {
        std::cout << "Maximum number of measurements recorded for HSI calibration" << std::endl;
        stopFlag.store(true);
    }
    else if (calError != Calibration::ErrorCal::None && calError != Calibration::ErrorCal::IgnoredMeasurement)
    {
        std::cerr << calError << " : Encountered when streaming data for HSI calibration" << std::endl;
        return static_cast<int>(calError);
    }
    thisThread::sleepFor(Microseconds(1000));
}
std::cout << "NumMeasKept: " << hsi.getMeasIndex() << std::endl << std::endl;

Finally, solve and print out the HSI calibration results. To view the solution in while performing the calibration, place the following code block inside of a while loop. The hsi.solve() computes the solution based on the measurements that were previously added to the HsiConfig object while the hsi.solution prints out the solution and figures of merit of the calibration to the user.

calError = hsi.solve();
if (calError != Calibration::ErrorCal::None)
{
    std::cout << calError << std::endl;
    return static_cast<int>(calError);
}

std::cout << hsi.solution;

After the calibration is performed, the VectorNav unit will need to be restored to its original state. The KnownMagneticDisturbance command will be set to NotPresent. By sending finalizeCalibrationOnSensor() with the saveSettings argument as false, the previous configuration is restored to the unit and the calibration written to the Magnetometer Calibration register (Register 23). To allow the calibration results to persist over a reset or a power cycle, a WriteSettings command should be issued to the sensor. If a WriteSettings command is not issued to the sensor, these calibration results will be erased upon a power cycle or reset.

latestError = sensor.knownMagneticDisturbance(KnownMagneticDisturbance::State::NotPresent);
EXIT_IF_ERROR("Encountered when disabling KnownMagneticDisturbance")

latestError = calSensConfig.finalizeCalibrationOnSensor(false);
EXIT_IF_ERROR("Encountered when restoring sensor configuration and writing calibration")

Finally, disconnect from the VectorNav unit.

sensor.disconnect();

Bias Calibration¶

Note

It is recommended to perform a bias calibration on VectorNav Industrial Series surface mount device (SMD) parts after installation and cleaning as the heat and stress from soldering the sensor will cause bias shifts.

All VectorNav sensors are calibrated for bias, scale factor, misalignment, and gyro g-sensitivity errors across the full temperature range of the sensor from -40°C to +85°C. This factory calibration is effective over the life of the part. However, due to the nature of MEMS inertial sensors, accelerometer and gyroscopes biases do drift over the life of the part regardless of the quality of the factory calibration. In rare circumstances, the biases on VectorNav Industrial Series sensors may drift enough to elicit a user calibration. A bias calibration can be performed on a VectorNav sensor using this tool within the Calibration plugin.

Motion Requirements¶

To properly estimate the inertial sensor biases using this tool, a bias calibration must be performed about the axis that is parallel to the gravity vector. The sensor must be placed on a flat surface before performing the calibration.

To perform a bias calibration, the following steps are recommended:

  1. Hold the sensor completely static for approximately 30 seconds.

  2. Rotate the sensor a minimum of 90 degrees about the axis parallel to the gravity vector over the course of a few seconds.

  3. Hold the sensor completely static for another 30 seconds.

If this type of motion is not feasible, contact VectorNav support for feedback on other calibration options.

Usage¶

Note

Ensure that the sensor is on a flat surface before performing the bias calibration.

The bias calibration can be run either by from a previously logged data file or while connected to the VectorNav unit.

Performing a Bias Calibration from a Data File¶

When performing a bias calibration using recorded data from a VectorNav unit, there are two different methods that can be used: the DynamicAccelBiasAuto method or the DynamicAccelBias method. The DynamicAccelBiasAuto method will automatically detect the different dynamic and static portions of the file, while the DynamicAccelBias method requires the user to manually split and add the measurements of the dynamic and static portions of their file. This is useful if a user desires more control over the static and dynamic portions of the calibration. The following example focuses on the DynamicAccelBiasAuto method.

To begin, a DynamicAccelBiasAutoConfig object must first be created. This allows the user to define the parameters needed for calibration. Once the configuration is set, a DynamicAccelBiasAuto object should be created, which will be used to add the calibration measurements and then solve for the estimated biases.

Calibration::DynamicAccelBiasAutoConfig config;

Calibration::DynamicAccelBiasAuto biasCalc(config);

When processing data from a previously recorded log file, a Sensor object must first be created and should be configured with MeasQueueMode::Retry.

Sensor::MeasQueueMode pushToCompositeData = Sensor::MeasQueueMode::Retry;  // do not allow overruns
Sensor sensor(pushToCompositeData);

Next, connect to the Sensor object using the inputted file path.

sensor.connect(filePath);

The data from the logged file is then loaded into the CalBase object for processing.

while (auto meas = sensor.getNextMeasurement())
{
    latestError = biasCalc.addMeasurement(*meas);
    if (latestError == Calibration::ErrorCal::None) { continue; }
    else if (latestError == Calibration::ErrorCal::IgnoredMeasurement) { ignoredCnt++; }
    else { std::cout << "Measurement " << ignoredCnt + biasCalc.getNumMeasAdded() << ": " << latestError << std::endl; }
}

To close the file, disconnect from the Sensor object.

sensor.disconnect();

Finally, solve and print out the bias calibration. The accelerometer bias solution should then be applied to the Accel Calibration register (Register 25) and the gyroscope bias calibration solution should be written to the Gyro Calibration register (Register 84) on the VectorNav unit. A writeSettings() command should be issued to the sensor in order for the calibration values to persist through a reset or power cycle of the sensor.

latestError = biasCalc.solve();
if (latestError != Calibration::ErrorCal::None)
{
    std::cerr << latestError << " encountered during solve." << std::endl;
    return (int)latestError;
}

Performing a Bias Calibration on a Connected VectorNav Unit¶

When performing a bias calibration with a connected VectorNav unit, a Sensor object first needs to be created. This object should then be used to connect to the VectorNav unit, such as by using the autoConnect() method.

Sensor sensor;
Error latestError = sensor.autoConnect(portName);

Once the Sensor object has been created and connected to the VectorNav unit, a DynamicAccelBiasConfig object must be created. This method empowers the user to clearly separate and control the static and dynamic components of the bias calibration process. Alternatively, the user can create a DynamicAccelBiasAutoConfig object that will automatically detect when the VectorNav unit is static and when the VectorNav unit is dynamic. This configuration object allows the user to define the parameters necessary for calibration. Once the configuration is set, the bias calibration object should be created which is where the calibration measurements will be added. For the manual detection method, two DynamicAccelBias objects must be created to allow for each static and dynamic cycle to be added to the previous cycle. If performing bias calibration using the automatic detection method, only one DynamicAccelBiasAuto object would be created since the automatic detection method performs the cycle saving by default.

Calibration::DynamicAccelBiasConfig config;
config.gval = 9.81f;

Calibration::DynamicAccelBias biasCal(config);
Calibration::DynamicAccelBias biasCalNext(config);

Next, the VectorNav unit must be properly configured for the calibration data collection. This can be done by creating a CalSensorConfig object, and calling the prepareSensorForCalibration() method. This method will read and store the VectorNav unit’s initial configuration and then write the required register settings for the calibration data collection. It is recommended to perform a WriteSettings command and save the current VectorNav unit’s settings by performing a Register Scan before calibration.

Calibration::CalSensorConfig calSensConfig(&sensor, &biasCal, Registers::System::AsyncOutputType::SerialPort::ActiveSerial, imuRate, gnssAided);
latestError = calSensConfig.prepareSensorForCalibration();
EXIT_IF_ERROR("Encountered when configuring Sensor for calibration.")

To collect data when performing a bias calibration on a connected VectorNav unit, a separate thread or loop needs to be created to obtain the unit’s most recent measurement and add it to the DynamicAccelBiasAuto or DynamicAccelBias object. In the BiasCalculatorFromSensor example, this thread is started and stopped by the user pressing the Enter key. It is recommended that the user configure the thread or loop to their application as it is not required the that the measurements be added to the DynamicAccelBiasAuto or DynamicAccelBias object using a key press.

VN::Thread keyPressThread{[]()
                          {
                              // 0 = Initial Dynamic
                              // 1 = Static (wait)
                              // 2 = Dynamic (Rotate)
                              // 3 = Static (wait)

                              std::cout << std::endl << "Press [Enter] to start calibration(s) once unit is stationary." << std::endl;
                              std::cout << "Press [q] then [Enter] to quit." << std::endl << std::endl;

                              while (isCollectingData)
                              {
                                  VN::thisThread::sleepFor(1ms);

                                  const auto c = std::cin.get();
                                  if (c == 'q')
                                  {
                                      isCollectingData = false;
                                      continue;
                                  }
                                  isStatic = !isStatic;

                                  if (isStatic) { std::cout << std::endl << "Press [Enter] to advance to the Dynamic step." << std::endl; }
                                  else { std::cout << std::endl << "Press [Enter] to advance to the Static step." << std::endl; }
                              }
                          }};

While the calibration thread or loop is running, the Sensor object is reading the measurements that were configured when setting the prepareSensorForCalibration() function. These measurements are added to the bias calibration. It is during this time that the motion requirements for the bias calibration would be performed. Once all motion requirements have been fulfilled, the thread or loop should be stopped and no more measurements should be added to the DynamicAccelBiasAuto or DynamicAccelBias object.

while (isCollectingData)
{
    const auto cd = sensor.getNextMeasurement();
    if (!cd || !(cd->imu.deltaTheta.has_value() && cd->imu.deltaVel.has_value())) continue;

    if (is_static != isStatic)
    {
        is_static = isStatic;
        if (is_static && biasCal.getState() == CalState::Dynamic) { biasCal.advanceState(); }
        else if (!is_static)
        {
            if (biasCal.getState() == CalState::InitStatic) { biasCal.advanceState(); }
            else if (biasCal.getState() == CalState::FinalStatic)
            {
                Calibration::ErrorCal calError = biasCal.solve();
                if (calError == Calibration::ErrorCal::None) { std::cout << biasCal.solution; }

                biasCal = biasCalNext;                                // copy over the InitStatic results
                biasCal.advanceState();                               // advance to Dynamic state
                biasCalNext = Calibration::DynamicAccelBias(config);  // reset for next cycle
            }
        }
    }
    if (biasCal.getState() == Calibration::DynamicAccelBiasState::FinalStatic) { biasCalNext.addMeasurement(*cd); }
    biasCal.addMeasurement(*cd);
}

Finally, solve and print out the bias calibration results. To view the solution while performing the calibration, place the following code block inside of a while loop. The biasCal.solve() computes the solution based on the measurements that were previously added to the DynamicAccelBiasAuto or DynamicAccelBias object while the biasCal.solution prints out the solution and figures of merit of the calibration to the user.

Calibration::ErrorCal calError = biasCal.solve();
if (calError == Calibration::ErrorCal::None) { std::cout << biasCal.solution; }

After the calibration is performed, the VectorNav unit will need to be restored to its original state. By sending finalizeCalibrationOnSensor() with the saveSettings argument as false, the previous configuration is restored to the unit and the calibration written to the Accel Calibration register (Register 25) and the Gyro Calibration register (Register 84) on the VectorNav unit. To allow the calibration results to persist over a reset or a power cycle, a WriteSettings command should be issued to the sensor. If a WriteSettings command is not issued to the sensor, these calibration results will be erased upon a power cycle or reset.

latestError = calSensConfig.finalizeCalibrationOnSensor(false);
EXIT_IF_ERROR("Encountered when restoring sensor configuration and writing calibration")

Finally, disconnect from the VectorNav unit.

sensor.disconnect();
